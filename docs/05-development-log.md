# 개발 진행 및 결과

재미로 만든 '낭독 부스'가 실제 온라인 행사에 쓰이고, 그 과정에서 만난 문제를 AI로 풀어 과제용 PoC로 정리하기까지의 기록입니다.

## 한눈에 보기

| 단계 | 기간 | 한 일 | 결과 |
|---|---|---|---|
| 1. 시작 | 10월 30일 | 텍스트를 읽어 주는 웹 화면(낭독 부스)과 사투리 음성 연결 | 브라우저 음성 + 녹음 속 인물 목소리 복제 |
| 2. 품질 | 10월 30일 | 문장 뒤에 붙는 잡음·웃음·엉뚱한 말 제거 | Demucs + faster-whisper 후처리 파이프라인 |
| 3. 안정화 | 10월 30일 | 메모리 과다 사용 해결 | 모델 공유 프로세스, 누수 3건 수정 |
| 4. 확장 | 11월 5일 | Typecast 연결 | 상용 TTS와 로컬 복제를 화면에서 선택 |
| 5. 현장 적용 | 11월 6~9일 | 진진가 게임 기능, ZEP 음성 전달 | 25명 대상 15분 게임 진행 |
| 6. 검증 | 11월 17일 | 본인 목소리로 20문장 평가 | 꼬리 잡음 15/20 → 0/20, 단어 잘림 0 |
| 7. 개선 | 11월 17일 | 현장 피드백 반영, 목소리 등록, 웹사이트 실행 | 질문 먼저 읽기, 누구나 내 목소리 등록, 터미널 실행 |

## 1. 시작: 낭독 부스

- 문장을 적고 읽기를 누르면 AI 목소리로 읽어 주는 웹 화면을 Claude 아티팩트로 만들었습니다.
- 음성 톤: 기본, 여성, 남성, 로봇(브라우저 내장 음성), 사투리(녹음 속 인물 목소리).
- 사투리 톤은 대본을 전라도 말투로 바꾼 뒤, 상용 TTS(Typecast)로 만든 녹음 속 인물 목소리를 오픈소스 모델 **Chatterbox Multilingual**로 복제해 읽게 했습니다.
- 화면에서 로컬 음성 서버를 부르기 위해 MCP 서버(`localvoice`)를 만들고 Claude 데스크톱 앱에 등록했습니다.
  - 처음에는 Claude Code 세션에만 등록해서 화면이 서버를 찾지 못했고(`server_not_connected`), 데스크톱 앱 설정에 등록한 뒤 해결했습니다.

## 2. 품질: 꼬리 잡음 제거

**문제**: 복제 목소리가 문장을 다 읽은 뒤에도 소리를 계속 만들었습니다. 웃음("흐흐흐"), 숨소리, 대본에 없는 말("안녕!"), 목소리보다 큰 음악·잡음이 붙어서 "읽는 중간에 배경 소리가 들어간다"고 느껴졌습니다.

**해결**: 생성 직후에 AI 후처리 두 단계를 붙였습니다.
1. **Demucs**(음원 분리)로 목소리 성분만 남겨 음악·잡음을 없앱니다.
2. **faster-whisper**(음성인식)로 대본의 마지막 단어가 끝나는 시각을 찾아, 그 뒤 첫 쉼에서 자릅니다.

**개발 중 실패와 수정**
- Whisper가 같은 음성을 매번 다르게 알아들어("죽겄네" → "주건데") 자르는 위치가 흔들렸습니다. 온도를 0으로 고정하고, 글자 대신 **자모 단위**로 대본과 맞추도록 바꿨습니다.
- 참조 녹음 자체에도 잡음이 있어 Demucs로 깨끗하게 만든 사본을 쓰고 원본은 따로 보관했습니다.

## 3. 안정화: 메모리

**문제**: Mac 메모리가 크게 부족해졌습니다.

| 원인 | 증상 | 해결 |
|---|---|---|
| Claude 앱이 음성 서버를 여러 개 띄우고, 각자 모델을 불러옴 | 서버당 약 5GB × 3 | 모델은 공유 작업 프로세스(worker) 하나에만 두고, 서버는 요청만 전달. 5분 동안 쓰지 않으면 종료 |
| Chatterbox 0.1.7이 문장마다 attention hook을 추가하고 지우지 않음 | 문장마다 약 1GB 증가 | 생성 후 새로 생긴 hook 제거 |
| 문장마다 참조 음성을 다시 처리 | GPU 메모리가 문장마다 약 1.1GB 증가 | 참조 음성 처리 결과를 캐시해 재사용 |

**결과**: 쉬고 있을 때 0GB, 읽는 동안 9~11GB에서 더 늘지 않습니다.

## 4. 확장: Typecast 연결

- Typecast API용 MCP 서버를 만들어, 사투리 톤에서 '내 Mac에서 복제'와 'Typecast 원래 캐릭터' 중 고를 수 있게 했습니다.
- 한 번 만든 문장은 저장해 다시 들을 때 크레딧이 들지 않게 했습니다.

## 5. 현장 적용: 진진가 게임

**진진가 패널**
- 다섯 항목 카드, 질문 입력, 추천 질문, 지난 질문 목록을 추가했습니다.
- 준비된 답변이 있으면 그것을, 없으면 Claude가 설정에 맞게 즉석 답변을 만들어 바로 읽습니다.
- 이름 고정, 증거 요청 거절 문구 같은 답변 규칙을 넣었습니다.
- 자동 읽기 켬/끔 버튼을 추가했습니다.

**ZEP 음성 전달**
- 낭독 부스 소리와 진행자 목소리를 섞어 ZEP 마이크로 보내기 위해 Loopback 가상 오디오 장치를 구성했습니다.
- 진행자는 블루투스 이어폰으로 듣고, Mac 내장 마이크로 말해 메아리를 막았습니다.

**실사용 결과**
- 참가자 25명, 약 15분 진행. 답변과 음성 모두 문제없이 나왔고, 참가자들은 거짓 두 개를 맞히지 못했습니다.
- **발견한 문제**: 질문이 몰리면 답이 어느 질문의 것인지 헷갈렸습니다.

## 6. 검증

- 본인 목소리(12.7초 녹음)로 20문장(표준어 10, 사투리 10)을 생성하고, 처리 전·후를 직접 들어 판정했습니다.
- 꼬리 소리 있는 문장 **15/20 → 0/20**, 단어 잘림 **0/20**, 문장당 후처리 **3.1초**.
- 자동 지표(글자 오류율, 꼬리 소리 크기)는 여러 번 틀려서, 사람 판정이 필요하다는 것도 확인했습니다.
- 자세한 내용은 [03-evaluation.md](03-evaluation.md)에 있습니다.

## 7. 개선

| 개선 | 계기 | 내용 |
|---|---|---|
| 질문 먼저 읽기 | 현장에서 답이 어느 질문의 것인지 헷갈림 | "지수님 질문, 고양이 이름이 뭐예요? 보리랑 콩이예요."처럼 읽기. `이름:`, `3번:` 형식 지원. 켬/끔 버튼 |
| 남성·로봇 톤 삭제 | 이 Mac에 자연스러운 한국어 남성 음성이 없어 여성과 똑같이 들림 | 기본, 여성, 사투리만 남김 |
| 내 목소리 톤 | 평가에 쓴 본인 녹음을 실제 화면에서도 쓰고 싶음 | 사투리 변환 없이 대본 그대로 복제 목소리로 읽기 |
| 누구나 목소리 등록 | 다른 사람도 자기 목소리로 듣고 싶음 | 화면에서 녹음하거나 파일을 올려 등록, 선택, 삭제. 삭제하면 그 목소리로 만든 문장도 함께 삭제 |
| 웹사이트 실행 | 검토자가 Claude 앱 없이 직접 확인해야 함 | `python web/serve.py`로 켜고 Ctrl+C로 끄는 로컬 웹서버. Claude 즉석 답변은 API 키가 있으면 동작 |
| 공개용 정리 | 개인정보와 상용 음성 보호 | 진진가 데이터를 가상 인물로 교체, 녹음·키·캐시는 저장소에서 제외 |

**개선 중 찾은 문제**: 저장소를 깊은 폴더에 두면 음성 엔진이 시작되지 않았습니다(Unix 소켓 경로 길이 제한). 소켓을 `/tmp` 아래 짧은 경로로 옮겨 해결했습니다.

## 남은 일

- 질문 먼저 읽기가 다음 게임에서 실제로 헷갈림을 줄이는지는 아직 확인하지 못했습니다.
- 블라인드 판정, 표본 확대, 수작업 편집 시간 측정은 [04-limits-next.md](04-limits-next.md)의 다음 단계에 있습니다.
