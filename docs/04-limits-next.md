# 한계와 다음 단계

## PoC의 한계

| 한계 | 영향 | 원인 |
|---|---|---|
| 문장 중간의 잡음은 못 지움 | 꼬리만 깨끗해짐 | 범위를 '마지막 단어 뒤'로 한정함 |
| 후처리가 문장당 약 3초 추가 | 즉석 답변이 그만큼 늦게 나옴 | Demucs와 Whisper를 CPU에서 돌림 (MPS 메모리 문제 회피) |

| 대본 끝을 못 알아들으면 자르지 않음 | 꼬리가 남을 수 있음 (평가에서는 0건) | 단어 잘림을 피하려는 의도된 선택 |

## 해 본 추가 시도

### 1. 모델 세 개를 하나의 파이프라인으로 연결
음성 생성(Chatterbox) → 음원 분리(Demucs) → 음성인식(faster-whisper)을 한 흐름으로 묶었습니다. 앞 모델의 실수를 뒤 모델이 바로잡는 구조입니다.

### 2. 메모리 누수 진단과 수정
실제로 쓰다 보니 Mac 메모리가 부족해지는 문제가 있었고, 원인을 셋 찾아 고쳤습니다.

| 원인 | 증상 | 해결 |
|---|---|---|
| 음성 서버가 여러 개 떠서 각자 모델을 불러옴 | 서버 하나에 약 5GB씩 3개 | 모델은 공유 작업 프로세스 하나에만 올리고, 서버들은 Unix 소켓으로 요청만 전달. 5분 동안 요청이 없으면 종료 |
| Chatterbox 0.1.7이 문장마다 attention hook을 추가하고 지우지 않음 | 문장마다 약 1GB씩 늘어나고 점점 느려짐 | 생성 후 새로 생긴 hook을 지움 |
| 문장마다 참조 음성을 다시 처리 | MPS 메모리가 문장마다 약 1.1GB씩 늘어남 | 참조 음성 처리 결과를 캐시해 재사용 |

결과: 쉬고 있을 때 0GB, 읽는 동안 9~11GB에서 더 늘지 않습니다. 12GB를 넘으면 작업 프로세스가 스스로 다시 시작합니다.

### 3. 실제 현장에 붙여 보기
- **낭독 부스 화면**: 5개 항목 카드, 질문 입력, 준비된 답이 없으면 Claude가 답을 만들어 바로 읽어 주는 기능
- **ZEP 연결**: Loopback 가상 마이크로 AI 목소리와 진행자 목소리를 섞어 참가자 전체에게 전달

### 4. 판정 도구
처리 전·후를 나란히 듣고 Y/N을 기록하는 로컬 페이지([eval/listen.html](../eval/listen.html))를 만들어, 사람 판정을 빠르고 재현 가능하게 했습니다.

## 다음 단계

**바로 할 수 있는 것**
1. **블라인드 판정**: 처리 전·후 순서를 섞어 다른 사람 3명 이상에게 들려주기
2. **수작업 시간 측정**: 오디오 편집기로 꼬리 자르는 시간을 5문장 이상 재서 시간 단축 효과를 숫자로 비교하기
3. **표본 늘리기**: 목소리 3개 이상, 문장 100개, 시드 여러 개
4. **Colab 노트북**: GPU 환경에서 누구나 같은 실험을 돌릴 수 있게 하기

**현장에서 나온 문제: 질문과 답 이어 주기**

25명 실사용에서 질문이 몰리면 답이 어느 질문의 것인지 헷갈렸습니다. 쉬운 것부터 이렇게 개선할 수 있습니다.

| 방법 | 내용 | 난이도 |
|---|---|---|
| ✅ 답변 앞에 질문 다시 말하기 | 답변을 읽기 전에 질문을 먼저 읽음. 예: "지수님 질문, 고양이 이름이 뭐예요? 보리랑 콩이예요." | **적용함** (아래 참고) |
| ✅ 질문 번호 붙이기 | 참가자가 "3번: 사진 있어요?"처럼 항목 번호를 붙여 물으면 "3번 질문, …"으로 읽고, 그 항목으로 답함 | **적용함** |
| 질문 대기열 화면 공유 | 지금 답하는 질문과 다음 질문을 화면에 띄워 ZEP로 공유 | 중간 |
| 비슷한 질문 묶어 답하기 | 같은 항목을 묻는 질문이 몰리면 한 번에 묶어 답하기 | 중간 (Claude로 질문 분류) |
| ZEP 채팅 자동 읽기 | 진행자가 질문을 옮겨 적지 않고 채팅을 바로 가져오기 | 높음 (ZEP 연동 필요) |

**적용한 내용** (낭독 부스, [web/nangdok-booth.html](../web/nangdok-booth.html))
- 진진가 패널에 **질문 먼저 읽기** 켬/끔 버튼을 추가했습니다. 기본값은 켬입니다.
- 진행자가 채팅 질문을 `이름: 질문` 형식으로 옮겨 넣으면 "이름님 질문, …"으로 읽습니다. `3번: 질문` 형식이면 "3번 질문, …"으로 읽고 3번 항목으로 답합니다. 형식 없이 질문만 넣으면 질문만 읽습니다.
- 질문이 30자보다 길면 앞부분만 읽고 "…, 이 질문이요."로 줄입니다. 답이 늦게 나오지 않게 하기 위해서입니다.
- 질문 읽기는 답변 음성 앞에만 붙입니다. Claude에게 넘기는 '이미 한 대답' 기록에는 넣지 않아, 답변 내용에는 영향을 주지 않습니다.
- 확인: 준비된 답변, 증거 요청 답변, 기본 답변 세 경로에서 대본 상자에 질문이 먼저 들어가는지 로컬에서 확인했습니다. 다음 게임에서 실제로 헷갈림이 줄었는지는 아직 확인하지 못했습니다.

**개선 아이디어**
- **생성 단계에서 막기**: Chatterbox가 문장 끝을 놓치는 신호(문장 끝 강제 경고, 반복 토큰)를 감지하면 그 자리에서 생성을 멈추기. 그러면 후처리할 꼬리 자체가 줄어듭니다.
- **더 가벼운 끝 찾기**: Whisper 대신 대본과 음성의 시간을 맞춰 주는 정렬 모델(forced alignment)을 쓰면 더 빠르고 정확한 단어 끝 시각을 얻을 수 있습니다.
- **사투리 음성인식 보완**: 사투리 음성으로 Whisper를 파인튜닝하거나, 사투리-표준어 변환표로 대본을 함께 비교하기.
- **실시간화**: 문장 단위가 아니라 구 단위로 생성과 후처리를 겹쳐서, 첫 소리가 나오기까지의 시간을 줄이기.
